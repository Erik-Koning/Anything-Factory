# Audit: the scaffolder, and checks that hold (2026-11-09)

Three independent reviews of `subscriptions-accounts..scaffolder-harness`, each given the code and not the author's
view: enforcement (can a member get round a rule), the runtime (the merge queue, the check after merges, locks), and
the page checks (do they tell the truth). "Ran" means a reproduction showed it; "traced" means the code was read end
to end. Nothing here is fixed yet.

### Tests missing

The queue's markers and a deferred check followed by a failed, light or paused merge; the fewer-tests refusal; a moved
commit, lock contention, a crashed suite, the app down, filing again after rejected or done; the suite's time limit;
`finish` and `complete`.

## Smaller

Owned commands with a variable in them (`a6g e2e $R`) pass the guard and are stopped only by the command's own role
check. Testers have no test lane at the merge queue. Discarded runs stay in the history. `.a6g/run/pages-auth` is
shared by worktrees; `e2e try` leaves its temporary folders; sign-in states aren't checked against `.gitignore`.
`A6G_APP_LOCK=held` is inherited by an app the after-merge command restarts. `pages run <unknown page>` exits 0, as
does `pages shots` on a failure. An invalid `mask` selector reads as "didn't load". There's no schema for
`harness.json`.

## Checked and sound

The guard refuses `e2e run`, `complete` and `harness allow` in every wrapped, quoted and nested form tried, including
inside `a6g env use … --`; clearing a member's identity is refused. An allowance holds for one commit. `@journey-1`
and `@journey-12` never mix. Finding keys don't collide. One check runs at a time and there's no deadlock. A crashed
configuration is never a pass for a journey. Done findings are filed again when the failure returns. The schema and
`lib/config.ts` agree. Clipping exceptions (ellipsis, line clamp, screen-reader-only text, scroll boxes), focus by
box shadow or `:focus-visible`, every scheme switch tried, slow fonts, tall pages and an unreachable app behave.
